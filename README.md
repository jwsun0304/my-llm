# my-llm

nanoGPT 스타일로 처음부터 구현하는 미니 GPT 프로젝트. 학습 목적 + 포트폴리오용.

## 진행 단계

1. [x] 미니 GPT 구현 (tokenizer, model, train, sample)
2. [x] Ablation 실험 (positional encoding / causal mask 제거 후 비교)
   - 2.5 [x] BPE 토크나이저 구현 + char-level과 bits-per-character 비교
3. [x] Optuna로 모델 크기 대비 성능/비용 트레이드오프 분석 + Colab T4 메모리 병목 분석
   - 3.5 [x] 스케일링 법칙 미니 실험
4. [x] 개인 RTL 프로젝트(코드+보고서) 기반 RAG 어시스턴트 (retrieval 75%, 수동 재채점 정답률 ~42% — 상세는 AI_USAGE_LOG 참고)
   - 4.5 [x] RAG vs LoRA 파인튜닝 비교 실험 — LoRA만 쓰면 수동 재채점 정답률 17%로 가장 위험(허위 인물명·허위 검증 이력 날조), RAG+LoRA는 RAG only와 동일(~42%)하여 이 규모 데이터에서는 파인튜닝의 추가 이득 없음
5. [x] 문서 정리 (AI_USAGE_LOG, 설계 근거)

## 왜 이렇게 설계했는지

이 프로젝트는 "LLM 튜토리얼을 따라 해봤다"가 아니라, 각 단계마다 **"왜 이렇게 했는가"에 실측 데이터로 답할 수 있는 것**을 목표로 설계했다.

- **1~2단계 (구조 이해)**: nanoGPT를 처음부터 구현한 뒤, causal mask/positional encoding을 각각 제거하는 ablation을 직접 돌렸다. causal mask를 없애면 미래 토큰을 그대로 참조하는 shortcut(label leakage)이 생겨 loss가 0.01까지 붕괴하지만 실제로는 생성 능력이 전혀 없는 모델이 된다는 것, positional encoding이 없으면 성능이 꾸준히 저하된다는 것을 직접 확인했다.
- **2.5단계 (토크나이제이션)**: char-level과 BPE를 동일 조건으로 학습해 비교했다. 서로 다른 vocab 크기를 가진 두 모델의 raw loss를 그대로 비교하는 것은 잘못된 방법이라 판단해, bits-per-character로 정규화했고, 그 결과 BPE가 같은 연산 예산으로 2배 넓은 문맥을 커버하면서 이미 char-level을 앞선다는 것을 확인했다.
- **3~3.5단계 (하드웨어 인지 엔지니어링)**: Optuna 탐색을 "최적 하이퍼파라미터 찾기"가 아니라 "모델 크기 대비 성능/비용 트레이드오프 분석"으로 재정의했다. 8-layer 모델이 4-layer보다 오히려 못한 것, T4에서 batch 128(14.3GB)을 넘기면 바로 OOM이 나는 것을 실측했다. 스케일링 법칙 실험에서는 데이터 축은 깨끗하게 스케일링됐지만 파라미터 축은 그렇지 않았는데, 이를 "실패"로 덮지 않고 고정된 iteration 예산 때문에 큰 모델이 상대적으로 undertrained였다는 Chinchilla식 해석으로 설명했다.
- **4단계 (실무 적용 + 정직한 검증)**: 지어낸 QA 데이터 대신 본인이 실제로 보유한 두 RTL 프로젝트(ECDH 가속기, LBIST)를 지식베이스로 RAG를 만들었다. 자동 채점 지표(키워드 매칭 기반 grounding rate)가 50%→75%로 개선됐을 때, 그 숫자를 그대로 믿지 않고 12개 답변을 전부 수동으로 재검토해 실제 정답률이 여전히 ~42%에 머물러 있다는 것, 그리고 자동 지표가 서로 다른 실험 결과를 섞은 답변(숫자는 진짜인데 결합이 틀린 경우)을 못 잡아낸다는 것을 발견했다.

## 한계와 스케일 안 되는 지점

포트폴리오에서 과장하지 않기 위해, 이 프로젝트가 실제 프로덕션 스케일과 다른 지점을 명시한다.

- **모델 스케일**: char-level 기준 최대 10.8M 파라미터, tiny-shakespeare(~100만 토큰) 규모. 실제 프로덕션 LLM(수십억~수천억 파라미터, 수조 토큰)과는 몇 자릿수 차이가 난다.
- **RAG 검색**: numpy 코사인 유사도로 271개 청크를 전수 비교하는 방식이라 소규모 코퍼스에서만 유효하다. 문서가 수만 개 이상으로 늘어나면 FAISS 같은 근사 최근접 탐색이 필요하다.
- **RAG 평가 지표**: 키워드 포함 여부로 grounding을 판정하는 방식은 "정답 관련 단어가 들어있는지"만 볼 뿐 여러 사실을 잘못 결합한 답변(서로 다른 실험 결과를 섞는 등)을 잡아내지 못한다. 이번엔 12문항이라 수동 재검토가 가능했지만, 문항 수가 커지면 LLM-as-judge 같은 자동화된 방법이 필요하다.
- **스케일링 법칙**: 축당 3개 데이터 포인트로만 로그-로그 기울기를 추정해, 통계적 신뢰구간은 없다. 정성적 추세 관찰 수준으로만 해석해야 한다.
- **학습 환경**: 단일 GPU(Colab T4)에서만 검증했고, 분산 학습이나 멀티 GPU 환경은 다루지 않았다.
